# 离线管理员公告保护

普通用户打开 ClassHub 后无需登录即可查看公告。发布、置顶、取消置顶和删除时，软件要求本地管理员验证；验证失败或取消窗口时，继续保留公告查看功能。删除公告还需确认。

## 首次部署与日常使用

1. 由教师或负责部署的管理员先运行软件，点击左侧“班级公告”，填写公告标题和正文并点击“发布”。如果尚未建立账户，将显示首次管理员设置窗口。一级模块目前仍是骨架，因此此次增加公告的直接导航入口。
2. 设置 1–64 个字符的账号和 12–128 个字符的密码，再次输入密码确认。密码不会被自动去除首尾空格；建议使用容易记住、难以猜测的长密码。
3. 账户成功保存后才授予此次操作权限；点击取消、输入无效或保存失败都不会授予权限。首次设置完成后，后续修改公告输入管理员账号和密码即可。
4. 每次公告修改均重新验证，并在操作结束后退出认证状态。服务层会再次检查权限，认证最长有效 2 分钟；超时需重新验证。连续失败 5 次后暂停验证 30 秒，关闭登录窗口不会清除失败次数。暂停期间仍可查看公告。

请在交给学生使用前完成首次管理员设置。账户尚不存在时，首次设置用于建立本机管理员身份；不会预置默认账号或默认密码。

## 本地数据与密码

软件运行时不需要网络，认证不会调用外部服务。数据保存在程序所在目录下：

| 文件 | 用途 |
| --- | --- |
| `Data/notices.json` | 原有公告数据，文件路径和公告格式保持不变 |
| `Data/accounts.json` | 管理员账户与密码哈希 |

密码使用 PBKDF2-SHA256，600,000 次迭代、每次独立生成的 16 字节随机盐及 32 字节结果，按带版本的格式保存。账户文件中没有明文密码。仅支持密码管理员；U 盘和密码与 U 盘组合认证保持拒绝状态，不会退化成仅验证密码。此次修改没有实现其他模块的授权或账户管理功能，账户服务中尚无受保护工作流的增删改接口明确拒绝调用。

账户文件每次验证和权限检查都会重新读取。账户停用、角色降级、密码哈希改变、身份变化或账户移除后，已有认证不能继续修改公告。公告读取和返回的账户对象均为副本，不能通过修改返回对象绕过服务权限。

## 保存失败、数据损坏与恢复

首次账户保存采用同目录临时文件和禁止覆盖的原子重命名，避免两次首次设置互相覆盖。公告保存也先写临时文件，成功提交后才更新内存；保存失败会提示错误并保留原内容。

空账户文件、无效 JSON、空列表、无效字段、重复账号或标识、不受支持的密码哈希和超过 1 MiB 的账户文件均视为无效数据。软件不会将这些情况当作首次运行，也不会自动重建管理员。公告仍可查看，修改操作保持锁定。不存在账户文件时才允许首次设置。

部署前备份 `Data` 目录，并在首次设置后保留有效的账户备份。恢复应在退出软件后由负责部署的教师或 IT 管理员进行，使用可信的 `accounts.json` 备份；公告文件可单独备份和恢复。当前没有找回密码或密码重置界面，不能把自动删除账户文件当作密码恢复机制。

这是应用内的权限保护。本机拥有数据目录写入权限的人可以修改、替换或删除本地文件，因此 Windows 文件权限仍是部署边界。按教室机器的实际账户配置限制程序和数据目录访问，妥善保护账户备份；若学生和管理员共用同一个可写的 Windows 账户，本应用无法阻止用户直接篡改文件。程序需要数据目录写入权限才能保存管理员和公告，请先由部署人员确认权限配置。

## 自动验证

在 Windows 和 .NET 8 SDK 环境下执行：

```powershell
dotnet restore ClassHub.Tests/ClassHub.Tests.csproj
dotnet build ClassHub.Tests/ClassHub.Tests.csproj --configuration Release --no-restore
dotnet test ClassHub.Tests/ClassHub.Tests.csproj --configuration Release --no-build
```

`ClassHub.Tests` 使用独立临时目录，不接触教室的实际数据。测试覆盖密码格式与随机盐、非法账户文件、首次设置及竞争、错误密码、身份伪造、禁用和非管理员账户、会话过期、失败锁定、账户变更撤权、游客只读、公告持久化与保存失败、防止通过返回对象修改数据，以及 WinForms 公告模块的 STA 构造检查。GitHub Actions 在 `windows-latest` 上自动构建并运行同一套测试。构建与测试依赖获取软件包时可能需要网络，已部署的软件认证和数据操作不依赖网络。

## 在实际 Windows 10 教室电脑完成的检查

- 在既有公告数据上启动升级后的程序，确认标题、正文、排序和置顶状态保留；不登录可以查看。
- 首次设置、正确登录、错误密码、取消登录、密码确认不一致、关闭窗口、失败 5 次后等待 30 秒的提示均清晰可见；失败后可继续查看公告。
- 发布、置顶、取消置顶及删除逐项验证；取消登录或删除确认时公告不变；完成每项操作后再次修改需要重新登录。
- 重启程序后账户仍可使用、公告仍保留；断网时重复上述操作。
- 在实际部署目录模拟无写入权限、无读取权限和损坏的账户备份，确认错误提示出现、公告仍可查看、不会自动重置管理员；使用可信备份恢复后再次验证。
- 在目标的 Windows 10 32/64 位电脑及 .NET 8 Windows Desktop Runtime 下试运行，检查 1366×768 等实际分辨率、100%/125%/150% DPI、中文字体、键盘 Tab/Enter/Escape、登录窗口遮挡和公告编辑布局。

自动测试中的窗口构造检查不等于人工操作测试。`windows-latest` 也不代表实际教室的 Windows 10 版本、DPI、权限配置和设备性能。
